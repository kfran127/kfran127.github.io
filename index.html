SecureBank IAM Lab

Designed and implemented a simulated banking identity environment in Microsoft Entra ID, incorporating Conditional Access, Privileged Identity Management, access reviews, and identity monitoring.

01 / Objective & environment

Build an identity security environment in a personal Microsoft Entra ID P2 developer tenant, using a simulated community bank to practice lifecycle management, access controls, and recurring governance. This is a personal lab, not a production bank deployment.

02 / Identity lifecycle

Organized 15 simulated employees into five department security groups. Documented Joiner/Mover/Leaver workflows covering provisioning, group-based application access, role changes, account disabling, and removal of access.

03 / Conditional Access & security controls

Configured five policies: baseline MFA, blocking legacy authentication, MFA plus compliant devices for executives, blocking high-risk sign-ins, and phishing-resistant MFA for admin directory roles. The README also documents self-service password reset and group-based access to two enterprise applications.

04 / Privileged Identity Management

Configured PIM settings for three privileged roles and documented eligible Security Administrator and User Administrator assignments, with just-in-time activation controls. These controls separate standing access from time-bound privileged access.

05 / Access reviews & entitlement management

Documented quarterly IT Security, annual Executive, and monthly Compliance access review campaigns, with access removal for non-response. A loan-officer access package includes approval, expiration, and an annual review.

06 / Identity monitoring

Connected Entra diagnostic logs to Azure Log Analytics. The repository includes basic KQL investigations for failed sign-ins, new user creation, and PIM role activity, tested against activity generated in the lab tenant.

07 / Lessons from the design

Group-based assignment connects lifecycle changes to application access. Privileged access needs both activation controls and audit visibility. Recurring reviews and expiring access packages help address stale access. These are design takeaways from the documented lab, not measured production outcomes.

Scope note: the repository marks administrative units as a future enhancement for the rebuild, despite earlier workflow references. They are not presented here as an implemented rebuild control.
